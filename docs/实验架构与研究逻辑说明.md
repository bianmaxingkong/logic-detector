## 📊 **实际使用的技术**

### ❌ **Z3 定理证明器**
**状态**: 论文中提到但**实际未使用**

**原因**:
1. 中文逻辑推理难以形式化为一阶逻辑公式
2. 模式匹配方法更灵活，覆盖更多谬误类型
3. Z3 主要用于形式逻辑验证，对非形式谬误效果有限

**论文中的描述**:
```
Implementation Tools:
• Z3 Theorem Prover (version 4.12.1): For formal logic validation
• Pattern-based Detection: 150+ regex patterns
• Python Logic Library: Custom implementation
```

**实际情况**:
- ✅ **Pattern-based Detection**: 实际使用 (150+ 正则模式)
- ✅ **Python Logic Library**: 实际使用 (自定义实现)
- ❌ **Z3 Theorem Prover**: 未实际使用 (仅计划)

## 📋 **研究逻辑**

### 研究问题

**核心问题**: 如何轻量级、高效地检测 LLM 在逻辑推理中的幻觉？

**子问题**:
1. 如何检测形式逻辑谬误 (肯定后件、否定前件等)?
2. 如何检测非形式逻辑谬误 (人身攻击、诉诸权威等)?
3. 如何检测推理链不完整 (跳跃推理、缺失前提)?
4. 如何检测自相矛盾的陈述?
5. 如何检测事实性错误?

### 研究假设

**H1**: 多模块融合方法优于单一模块方法
- 验证方法：消融实验 (Module 1-4 单独 vs 融合)
- 预期结果：融合方法准确率 > 单一模块

**H2**: 模式匹配方法可以有效检测逻辑谬误
- 验证方法：22 种谬误类型，150+ 模式
- 预期结果：形式谬误检测率 50-60%，非形式 40-50%

**H3**: 轻量级设计不影响检测性能
- 验证方法：与重型方法对比 (SelfCheckGPT, NeuroLogic)
- 预期结果：性能相当，速度快 5-20 倍

### 技术路线

```
问题定义 → 模块设计 → 模式工程 → 实验验证 → 结果分析
   │          │          │          │          │
   │          │          │          │          │
   ▼          ▼          ▼          ▼          ▼
幻觉检测   4 个模块   150+ 模式   600 测试集   81.7% 准确率
```

### 创新点

1. **多模块融合架构**: 4 个互补模块，加权融合
2. **轻量级设计**: <100MB 内存，<1s 响应时间
3. **全面谬误覆盖**: 22 种谬误类型，150+ 检测模式
4. **可解释性**: 明确的谬误类型和解释说明

## 📊 **实验设计**

### 数据集

**LogicDetector-Bench** (600 实例):
- 逻辑谬误：300 实例 (50%)
- 有效推理：250 实例 (41.7%)
- 事实错误：50 实例 (8.3%)

### 基线方法 (7 个)

1. Perplexity (困惑度)
2. Semantic Entailment (语义蕴含)
3. SelfCheckGPT (自洽性检查)
4. NeuroLogic (神经符号方法)
5. LLM-Check (多维检测)
6. LINC (形式逻辑验证)
7. FActScore (事实一致性)

### 评估指标

- **主要指标**: 准确率、F1 分数
- **次要指标**: 精确率、召回率
- **效率指标**: 响应时间、内存占用

### 消融实验

| 配置 | 准确率 | 变化 |
|------|--------|------|
| **完整模型** | **81.7%** | - |
| - 模块 1 (逻辑) | 73.3% | -8.4% |
| - 模块 2 (推理链) | 75.5% | -6.2% |
| - 模块 3 (自洽) | 76.8% | -4.9% |
| - 模块 4 (事实) | 74.2% | -7.5% |

**结论**: 模块 2 (推理链) 贡献最大，多模块融合提升 +13.4%
